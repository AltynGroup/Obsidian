# Decisions.md — какие решения уже приняты и почему

**Статус:** draft.
**Дата:** 18 ноября 2026.

**Цель документа:** фиксировать принятые решения, обоснование выбора и время принятия, чтобы в будущем не переписывать историю проекта.

---

## Формат записи решения

| Поле | Обязательно | Значение |
|---|---|---|
| ID | Да | Dnn или область: D1, D2 ... |
| Решение | Да | Коротко, что решили |
| Когда | Да | Дата изменения (YYYY-MM-DD) |
| Кто | Нет | Автор решения (имя / роль) |
| Почему | Да | Аргумент выбора |
| Статус | Да | Принято / Изменено / Отменено |
| Последующие следствия | Нет | Что это вызвало |

---

## Принятые решения

| ID | Решение | Когда | Почему | Статус |
|---|---|---|---|---|
| D1 | Создать общую базу знаний экосистемы Altyn в Obsidian | 2026-11-18 | Нужно единое место для разработчиков, AI-агентов и сотрудников, чтобы не распыляться по многочисленным файлам и чатам | Принято |
| D2 | Использовать Markdown, YAML frontmatter и относительные ссылки | 2026-11-18 | Соответствует AGENTS.md, совместимо с Obsidian и удобно для AI и людей | Принято |
| D3 | Не делать коммиты или push без явного разрешения | 2026-11-18 | Из правил AGENTS.md и требований безопасности | Принято |
| D4 | Верифицировать данные токенов через публичные источники (Solscan, TonAPI, TonScan), а не додумывать | 2026-11-18 | Требуется, чтобы не писать ложных технических фактов | Принято |
| D5 | Создать отдельные страницы для токенов ALTYN на Solana и TON | 2026-11-18 | Формирует важную часть базы; токены разные, нужны отдельные страницы | Принято |
| D6 | Сохранить пустые папки 01–07 как «открытые зоны» до подтверждения владельцем | 2026-11-18 | Пустые папки демонстрируют охват, но не шумят репозиторий своим отсутствием | Принято |
| D7 | Ввести статусы «Реализовано / Запланировано / Идея» для дорожной карты | 2026-11-18 | Чётко разделяет сделанное от плановых и несерьёзных идей | Принято |
| D8 | Не использовать Roadmap как обещание дедлайнов | 2026-11-18 | Roadmap — живой план, который меняется с появлением новых данных | Принято |
| D9 | Создать отдельные docs: Roadmap.md, Current-Tasks.md, Decisions.md | 2026-11-18 | Помогает чётко отделять стратегию от текущей работы от архитектуры решений | Принято |
| D10 | При работе с клиентом использовать «реализовано / запланировано / идея» | 2026-11-18 | Избежать вводящих в заблуждение обещаний и сужений | Принято |
